## Развёртывание контейнера KRSL

`vercel.json` объявляет приватный сервис `krsl` и binding из основного backend.
У Python-контейнера нет публичного rewrite: вызвать его может только связанный
backend. Для этой доверенной внутренней связи используется
`ml/krsl/Dockerfile.vercel`; обычный `Dockerfile` сохраняет проверку токена для
внешнего самостоятельного хостинга.

В настройках Vercel у проекта должен быть выбран Framework Preset **Services**
(Settings → Build and Deployment). GitHub API пока не показывает deployment
для commit `7f9fe35`, значит публикация от push автоматически не запускалась.
Когда доступ к панели будет открыт, выбери этот preset и создай Production
deployment из `main`.

При следующем успешном Production deployment оба сервиса должны собраться
вместе. Затем проверь `/api/krsl/status`: при успешно загруженной модели там
будет `ready: true`. Использование Vercel Services считается по вычислениям,
памяти, внутренним запросам и переданным данным; следи за лимитами проекта.
В Vercel-контейнерах ограничение тела запроса — 4.5 MB, поэтому в Production
лимит видео понижен до 4 MB, а камера записывает короткие сегменты с низким
битрейтом.

Подключение включает текущий экспериментальный Conformer, но не исправляет
его точность.
Для произвольных фраз нужна размеченная выборка с согласиями участников,
проверенными RSL-специалистами переводами и разделением train/validation/test
по разным людям. Текущий классификатор 12 отдельных выражений имеет низкое
покрытие и не прошёл допуск; универсальное распознавание фраз пока недоступно.

Большие публичные файлы исключены из исходной загрузки Vercel. Docker вызывает
`frontend/scripts/prepare-cloud-assets.mjs`: 543 файла восстанавливаются из
публичного GitHub по фиксированному коммиту в `cloud-assets.json`, с проверкой
размера и SHA-256 каждого файла. Нельзя менять только файл в `public` и оставлять
старый манифест: при следующем изменении этих ресурсов сначала опубликуйте их в
GitHub, затем обновите revision/хеши/размеры в манифесте и список исключений

## Обновление сайта

Текущая версия опубликована из локальной рабочей папки; автоматическое развёртывание из GitHub не подключено. Для следующих изменений запускайте из корня проекта `npx vercel deploy --prod --scope yasmina11`. Не публикуйте одну только папку frontend.

В Vercel production настроены секреты `ConnectionStrings__Default` (прямой PostgreSQL endpoint, SSL VerifyFull, пул до 10 соединений) и `Jwt__Key`. Preview имеет отдельный JWT-секрет, но отдельная preview-база ещё не подключена: перед preview-развёртыванием подключите изолированную БД. Не используйте production-базу для автоматических тестов или preview.

`Hosting__PublicOrigin` необязателен для текущего домена: сервер проверяет HTTPS Origin относительно входящего Host, что подтверждено проверками. `Database__Provider=Postgres`, `Hosting__Vercel=true`, `PORT=80`, Production и временный каталог заданы в Dockerfile. Пользовательские данные хранятся в PostgreSQL, не в файловой системе контейнера.

`.vercelignore`, `.dockerignore` и `.gitignore` исключают локальные базы, ключи и .env из публикации. Архив исходников не содержит облачных реквизитов.
